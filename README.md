# 🧪 Testing en Python con pytest

Aprende a escribir pruebas automatizadas que **fallan por la razón correcta**: desde tu primer `assert` hasta un proyecto con pruebas unitarias y de aceptación. Es para quien sabe Python básico y quiere probar su código con el criterio que se espera en un trabajo.

| 🧱 Bloques | 🧪 Labs | ⏱️ Por lab | 🛠️ Stack |
|---|---|---|---|
| 1 | 5 + 1 proyecto | 1–2 h | Python 3.12+ · pytest 9.2 · pytest-cov 7.1 |

## 🚀 Empieza
1. Instala todo con [SETUP.md](SETUP.md).
2. Guarda tu trabajo en tu propia rama (`git switch -c solutions/tu-nombre`) o en un fork.
3. Abre el [SYLLABUS.md](SYLLABUS.md) y empieza por el lab 1.1.

## 🧭 Cómo funcionan los labs
- 💭 **Concepto:** lees, luego respondes la autoevaluación.
- 🧩 **Reto:** el código ya funciona; **tú escribes las pruebas**. Una *caza de mutantes* las pone a prueba: deben pasar con el código real y fallar contra versiones con bugs sembrados. `solution/` está a la vista a propósito: tú decides cuándo mirar.
- 🔭 **Exploración:** una `demo/` terminada; predices, ejecutas y comparas.
- 🏗️ **Proyecto:** al final del bloque. Constrúyelo desde `BRIEF.md` y compáralo con `reference/`, o revisa la referencia con `REVIEW.md`.
