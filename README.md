# 🧪 Testing en Python con pytest

Aprende a escribir pruebas automatizadas que **fallan por la razón correcta**: desde tu primer `assert` hasta mantener una suite en equipo. Es para quien sabe Python básico y quiere probar su código con el criterio que se espera en un trabajo.

El camino sube la pirámide de pruebas en cuatro bloques: pruebas unitarias, de integración, de aceptación y la calidad de la suite. **El bloque 1, pruebas unitarias, está listo**; los demás están planificados en el [sílabo](SYLLABUS.md).

|---|---|---|---|
| 4 (1 construido) | 6 labs + 1 proyecto | 1–2 h | Python 3.12+ · pytest 9.2 · pytest-cov 7.1 |

## 🧭 Cómo funcionan los labs
- 💭 **Concepto:** lees, luego respondes la autoevaluación.
- 🧩 **Reto:** el código ya funciona; **tú escribes las pruebas**. Una *caza de mutantes* las pone a prueba: deben pasar con el código real y fallar contra versiones con bugs sembrados. `solution/` está a la vista a propósito: tú decides cuándo mirar.
- 🔭 **Exploración:** una `demo/` terminada; predices, ejecutas y comparas.
- 🏗️ **Proyecto:** al final del bloque, una aplicación terminada a la que le escribes la suite completa a partir de `BRIEF.md`. Una caza de mutantes de toda la aplicación la acepta. También puedes solo revisar la suite de referencia con `REVIEW.md`.

Cada lab presenta primero la idea, con un ejemplo, y después cómo la escribe pytest. Los términos del oficio quedan en inglés, con su traducción la primera vez: así los vas a encontrar en el trabajo.
